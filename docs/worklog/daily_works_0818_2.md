## 六、搬東西的連鎖：五條測試因為「控制項不在原地」而紅

改完之後跑完整 e2e，除了 R2 CORS 那兩條（外部卡住），另外五條全紅，
而它們的共同原因都是同一件事：**驗的東西搬家了**。

```text
homepage「完整六級價格呈現於首頁」   §26.1 的位置變了。改成驗
                                     「看得到起價」+「走得過去」，
                                     六級完整由 pricing-playground.spec 驗
project-builder ×2                   在首頁填品牌名稱再去 /start。
                                     改成去 /playground 填——仍然是真的操作，
                                     那正是這條測試的意義
preview-assistant「最窄的裝置」       需要切裝置。那一條自己去 /playground
admin-cms「改了價格，首頁跟著變」     首頁不再渲染 summary。改成兩端各驗一個欄位
```

### ⚠️ 其中一條紅的原因不是它自己

`homepage` 那條在找「免費」，而畫面上是「NT$ 111」——
那是 `admin-cms` 上一條測試寫進去的值。

它的 `afterAll` 用 **SQL 刪掉那一列**，而 CMS 的讀取端有快取、
**快取只在 action 存檔時失效**。所以 SQL 刪除之後，
前台最長一小時內還是那個測試值，把後面每一支測試都汙染掉。

那正是待辦上記著的那條地雷（「繞過應用層改資料庫，前台不會跟著變」），
只是這次是測試踩到的。修法：那一條測試在結束前**走存檔那條路把值改回去**——
之後快取裡的值 == 程式碼的預設值，`afterAll` 再刪掉那一列，兩邊就都乾淨。

> 這件事值得記住：**e2e 之間會透過快取互相影響**，
> 而症狀會出現在一支完全無辜的測試上。

## 八、CRM Dashboard

`/account/crm/[id]` 上方加概況，`/account/crm` 的清單加筆數。

⚠️ **統計全部從使用者自己的定義算出來**——與記錄表單、與後台的 CMS
編輯器同一招。寫死「客戶數與成交率」的話，一個拿它記食材庫存的人
會看到兩個永遠是 0 的數字，而那比沒有 dashboard 更糟。

### 每一種欄位能說什麼、不能說什麼

```text
select      各選項各幾筆，**含 0 筆的**。「沒有人選過這個狀態」
            往往正是最有用的資訊，只列出現過的值等於把它藏起來
checkbox    是 / 否，而且不算填寫率——沒勾也是一個答案。
            算成「沒填」的話，一份大家都沒勾的資料會顯示「填寫率 0%」
number      總計與平均。一筆都沒填時**不給平均**：
            「平均 0」與「還沒有資料」是兩件完全不同的事
date        最早與最晚
text        只有填寫率。硬要分組會得到一堆各 1 筆的「分類」——
            長條圖畫出來很專業，看的人要花時間才發現它什麼都沒說
```

### 三件在做的時候抓到的

```text
1. 分母是 0 → CSS 拿到 NaN%
   瀏覽器會忽略整條寬度宣告，結果每一條都變成滿版，
   看起來像「全部都是 100%」

2. 沒有資料時不畫一整排 0
   那看起來像壞掉，而它只是還沒開始。說出下一步比展示空數字有用

3. ⚠️ 日期欄位被說成「文字欄位不做分組」
   條件式寫成「沒有分布、沒有數字、沒有範圍」——而一個還沒有人填的
   日期欄位也滿足它。**不是壞掉，是說錯話**，而說錯話的圖表比沒有更糟。
   改成用型別判斷，並補了一條 e2e 盯著
```

`no-hardcoded-design-values` 也擋了一次：長條的高度我原本寫成
`height: ${...}px`，那個 px 值是一個只存在於該檔案的設計數值。
改成容器用 class（`h-12`）、inline 只留百分比，然後才進具名例外清單。

統計本身是純函式（11 條單元測試），畫面另有 2 條 e2e 驗「數字真的接上了」。
兩層都故意改壞驗過。

## 九、現場修復：管理員帳號存不了任何東西

Luffy 回報：按「存到我的帳號」→「存檔失敗。」，而且確實已登入。

### 原因

`crm_definitions.owner_id` 外鍵指向 `profiles`，而那個帳號建立於
`2026-08-10`——比 `profiles` 與 `on_auth_user_created`
（`20260811000005`）早一天。trigger 是 `after insert`，
對已經在 `auth.users` 裡的列不會觸發。

**那份 migration 上線的當下就已經有一個孤兒帳號。**

而它自己的註解寫著：

> 任何一處漏掉就產生沒有 profile 的孤兒帳號，而那不會有任何徵兆。
> 守在資料庫層才守得住。

那個判斷完全正確。它守住了未來，沒有回頭看一眼現在。

### 為什麼一週都沒發現

```text
e2e 全綠              每支測試都自己建新帳號，trigger 會補 profile。
                      測試涵蓋的永遠是「新使用者」——
                      而唯一的舊使用者沒有任何測試碰過
應用層吞掉錯誤         資料庫回的是
                        violates foreign key constraint …
                        Key (owner_id)=(…) is not present in table "profiles"
                      而使用者看到四個字，伺服器紀錄裡什麼都沒有。
                      **沒有任何人有辦法查。**
```

九張表外鍵指向 profiles，所以那個帳號存不了 CRM 設計、存不了網站草稿、
**也存不了任何後台 CMS 內容**。CMS 那一支剛好把原始訊息帶出來了，
所以它不是靜默的——但也沒有人去按過。

### 修了三件，而不是一件

```text
回填   欄位邏輯與 handle_new_user() 一字不差。
       分岔的話，回填出來的名字會與註冊產生的不一樣，
       而那種差異只有在同一個畫面上並排時才看得出來

守衛   「有沒有哪個 auth.users 沒有 profile」——反過來問。
       ⚠️ 只有在真資料庫問得出來：單元測試沒有 auth.users，
       e2e 只涵蓋自己建的新帳號。這條放進 test:db
       故意刪掉一個 profile 驗過會紅，訊息直接說出後果
       （「它們存不了任何東西」）

診斷   save-error.ts。原始錯誤一定進伺服器紀錄，
       給使用者的那句不含資料表名／欄位名／約束名。
       這一行就是這次事故裡唯一缺少的東西——
       資料庫已經說清楚了，而沒有人聽得到
```

> 這一件同時是兩種毛病：**回填漏掉**（宣告了 trigger 卻沒處理既有資料），
> 以及**吞掉錯誤**（有徵兆，但被摘成一句沒有資訊的話）。

```text
   改成用「有圓角邊框的那一層」去量。兩個方向都驗過會紅

4. 判準用錯：`documentElement.scrollWidth - clientWidth`
   站上別處的斷點測試都用這個減法，而它們的頁面沒有捲動容器。
   這一頁有——390 的視窗量出 429，而 `window.scrollX` 推到 9999
   之後仍然是 0：整頁根本捲不動。
   用那個減法的話，這一條會在一個**沒有發生的問題**上永遠紅著
```

還有一件不是我弄出來的：測試之間互相依賴（後面幾條靠前一條存的設計），
單獨用 `-g` 跑時全部紅，而紅的原因與它們要驗的事無關。
改成每條自己建自己的。
