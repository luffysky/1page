## 一、這一天最重要的一件事

**`audit:wiring`【3】報「沒有未接線的欄位」，而三張表一行程式碼都沒有。**

`invoices`、`invoice_lines`、`payments` 在 0814 就跑完 migration 了，
之後沒有寫過任何 repository、action 或頁面。稽核每天都綠。

原因是這一行：

```js
const neverUsed = [...columnNames].filter(
  (name) => !ignored.has(name) && !allSource.includes(name),
);
```

**整份原始碼的子字串比對。** `invoices.number` 會被
`typeof value === "number"` 裡的 `number` 命中；`total`、`status`、
`amount`、`method`、`note` 也全部一樣。三張表的每一個欄位都「被用到了」。

這是 CLAUDE.md 第二條的教科書版本：守衛在叫，但叫的內容是假的。
而它比沒有守衛更糟——因為每天早上看到那個綠勾，就不會再去想這件事。

### 改成兩層

```text
3a  有沒有哪一張表，from("…") 從來沒有出現過
3b  欄位只在「提到那張表的檔案」裡找，而且整字比對
```

3a 才是真正重要的那一條：**整張表沒接線 = migration 跑了但功能沒做**，
而那是這個專案第一種毛病最大的一個版本。

改完之後 3b 一開始噴出三個警告，其中兩個是我自己造成的誤報：

```text
admin_users.note          由 scripts/admin-create.mjs 寫入，
                          而稽核只掃 src——加掃 scripts/*.mjs 就好
portfolio_media.thumbnail_url
                          寫在 from("portfolio_projects") 的巢狀 select 裡，
                          那個檔案永遠不會出現 from("portfolio_media")
                          → 欄位比對改用寬判準（檔案提到表名就算）
activities.actor_id       真的沒有讀取端。由 trigger 以 auth.uid() 寫入，
                          TypeScript 裡看不到 → 具名例外並寫理由：
                          目前只有一位員工，多人之後要顯示
```

**驗證方式**：把 `payments` 的每一處 `from("payments")` 改成
`from("payments_disabled")`，稽核紅了並指名 `payments`。
（第一次只改了 `invoices.ts` 沒改 `actions.ts`，稽核照樣綠——
那不是稽核有問題，是我沒把改壞做徹底。）

## 二、BG：請款與收款

上面那件事逼出來的。三張孤兒表現在接起來了。

**這一塊沒有金流，也不打算有。** invoices 與 payments 是記帳：
自己開發票、自己對帳，系統只把「誰欠多少、收了沒」記下來。
畫面上寫著「這裡只是記帳，不會真的去收錢」，而且有一條 e2e 盯著那句話。

做成看起來會自動收錢的樣子，比沒有更糟——那是 SMTP 那件事的同一個教訓。

### 四個守衛，四次故意改壞

```text
明細改了要重算總額並存回去
  改壞：加明細後不重算  → 紅（DB 的 total 還是 0）
  為什麼重要：兩份真相最典型的樣子。客戶收到的金額與系統裡的不一樣，
              而畫面上完全看不出來

收款不會自動翻狀態
  改壞：收款後自動 update status = 'paid'  → 紅
  為什麼重要：收了一半就標成已收款，「還差多少」再也算不出來——
              而那是這整張表存在的理由

草稿以外一定要有開立日期
  改壞：拿掉檢查  → 紅
  為什麼重要：沒有日期的已寄出，回答不了「這筆帳放了多久」，
              而那是催款時唯一有用的資訊

重複編號要說人話
  改壞：拿掉 23505 的處理  → 紅，畫面上出現
        duplicate key value violates unique constraint "invoices_number_key"
  為什麼重要：看得懂那句話的人不需要這個系統
```

### 金額一律用整數的分算

`0.1 + 0.2 !== 0.3` 在請款單上的表現是「明細加起來與總額差一塊」，
而那一塊沒有人解釋得了。單元測試裡有一條直接驗 `0.1 × 3`。

### 稅率不存欄位

migration 只存結果（subtotal / tax / total）。那是刻意的：
**已經開出去的請款單金額不能因為之後改稅率而變**。
編輯時從 `tax / subtotal` 反推回百分比當預設值，不是套用「現在的稅率」。

## 三、後台的 RWD/a11y 清單過期了六個頁面

`authed-breakpoints.spec.ts` 的後台段落寫死三條路由：
`/admin`、`/admin/portfolio`、`/admin/portfolio/new`——那是 2E 當時後台的全部。

之後加的收件匣、客戶、報價、專案、請款、內容管理**一條都沒有被掃過**，
而這支測試的名字說它在檢查「後台」。

改成從磁碟列舉，動態路由列成具名例外並寫明「誰在掃它」。
結果：22 個 route × viewport 組合，全部通過（含這一天新做的請款頁）。

順帶抓到一個我自己寫的 a11y bug：請款單的提醒區塊是
`<ul role="status">`——給 `<ul>` 一個 role 會**取代**它的 list 語意，
裡面的 `<li>` 就變成沒有列表父容器的孤兒。axe 報 `listitem`。
改成外層 `<div role="status">` 包一個乾淨的 `<ul>`。

## 四、這一天更早做的（BE / BF / BI / BJ）

### BE — 報價與成交

未成交一定要寫原因，**兩層都擋**。資料庫的 check constraint 是真正的
邊界（任何寫入路徑都繞不過去），action 那一層是為了說人話——
拿掉它之後畫面上出現的是
`violates check constraint "deals_lost_needs_reason"`。

原因欄位只在選了「未成交」時出現，而且**不加 `required`**：
瀏覽器的必填氣泡一秒就消失，我們自己那句話才留在畫面上。

### BF — 專案、里程碑與工時

工時存分鐘，輸入收「90」「1:30」「1.5h」。要求每次心算成分鐘的話，
實際發生的事是他不記——而沒記的工時等於沒發生過。
看不懂就回 null 並說出來，不猜：猜一個值的話，打錯的那一次會安靜留下
一筆看起來很正常的錯資料。

顯示成「1 小時 30 分」而不是「1.5 小時」。存分鐘就是為了避開
「0.30 是 18 分還是 30 分」的誤會，顯示時換回小數等於把它請回來。

### BI — 全站每一頁每個區塊都可以在後台改

內容管理從 2 份長到 14 份。編輯介面從 JSON 換成**表單**——
照著內容的形狀長出來，所以加新 key 不用動編輯器（與 content-panel 同一招）。
JSON 留在「進階」後面。

兩條新守衛都是**反過來問**的形式：

```text
登記了但沒有任何地方讀的 key    CMS 特別容易犯：後台清單直接讀 registry，
                                登記了就編得了、存得進去，完全不需要有人讀它。
                                失敗的樣子是「按了儲存說存好了，網站上什麼都沒變」
SECTION_COPY 裡有沒有哪一段     從 config 算出來，下次加新 Section 時它自己會發現
還沒搬進 CMS
```

順手修掉登入頁的「此頁供工作人員使用」——CR-002 之後那句話就不成立了，
一般會員也從這裡進自己的後台。一句過期的說明會讓真的想登入的人
以為自己走錯地方。

### BJ-1 — 每一塊都可以換背景

純色／漸層／圖片／影片。參考 MaoTravelBlog 的 PropertyPanel，
但三個地方刻意不一樣：

```text
遮罩預設不是 0              照片上壓文字幾乎一定對比不足，而那件事在自己的
                            螢幕上看不出來——因為看的人已經知道那行字寫什麼
reduced-motion 不用 CSS 藏  純 CSS 只能藏：影片仍然會下載、會播，耗流量耗電，
                            而且哪天有人拿掉那條 CSS 行為就悄悄變回去。
                            改成問過之後才決定要不要**放** video 元素
背景整層 aria-hidden        它是裝飾，不是內容
```

媒體上傳因此開始收影片。那個 action 原本的註解寫著「網站區塊沒有任何
地方會播影片——收得進來卻沒有人讀，那就只是一個 100MB 的上傳孔」，
現在真的有讀取端了，所以條件與理由一起改。

**又抓到一個我自己寫的假守衛**：「背景不會被讀螢幕的人讀到」原本只跑 axe，
而把 `aria-hidden` 整個拿掉之後 axe 照樣全綠——那條測試從來沒在驗
它名字說的事。改成直接問結構。

### BJ-2 — 首頁版面可以在後台排

拖曳排順序、開關每一塊、每一塊設背景。拖曳與鍵盤呼叫同一個純函式
（WCAG 2.1 §2.5.7），有一條測試驗兩者結果相同。

**界線寫在編輯器上方，不是只寫在註解裡**：首頁那些區塊不是文字方塊。
目標選擇器是整頁的 context controller、AI 顧問是真的會對話的介面、
模板體驗裡面是一整個預覽引擎——它們搬得動、關得掉，但沒辦法再拖一個進來。

做一個看起來什麼都能拖、實際上只有三種積木有用的畫布，比誠實說明更糟：
前者要等使用者拖了半天才發現。

區塊清單由程式碼決定，資料裡少了某一塊時**補回來並保持顯示**。
省略的話，新做好的區塊在「按過存檔」的環境上永遠不出現，
而在沒按過的環境上正常——那種差異的表現是「我這邊看起來好好的」。

## 五、順手發現的兩件事

### `no-hardcoded-design-values` 自己踩了 comment-vs-code 地雷

CLAUDE.md 記著：「稽核腳本比對原始碼前要先去掉註解。同一個原因造成過
一次假通過、一次假失敗。」這次是**假失敗**——背景模組在註解裡解釋
「為什麼不寫死一個 rgb(0 0 0 / x)」，而這條規則把那句解釋本身當成違規。

改成比對前先去掉註解，並確認寫死在程式碼裡的色碼仍然抓得到
（在一個沒有例外的元件裡塞一個 `#ff0000`，紅了）。

### 繞過應用層改資料庫，前台不會跟著變

CMS 的讀取端有快取，而快取由 tag 失效，**tag 只在 action 存檔時被打掉**。
用 SQL 直接刪掉 `cms_documents` 的那一列之後，首頁最長一小時內還是舊的。

這不是 bug，是設計的一面，但它讓 e2e 的收尾不能只用 SQL 清資料——
`admin-layout.spec.ts` 因此多了一顆「回到預設版面」按鈕與一條收尾測試。
那顆按鈕本身也是真的需要的功能：關掉三塊、搬了五次之後，
沒有人想得起來原本的順序。
